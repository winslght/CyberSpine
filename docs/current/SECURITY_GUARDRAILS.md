# CyberSpine 安全准则

## 1. 安全目标

CyberSpine 是 Windows 本地感知与受控动作系统。安全设计必须始终优先于功能便利：保护用户隐私、维持用户对本机动作的控制、限制插件和外部组件权限，并让关键决策可审计。

## 2. 感知与隐私

- **数据最小化**：只采集完成功能所必需的信号；默认不采集输入内容、原始剪贴板内容、屏幕图像、精确鼠标轨迹或无关窗口内容。
- **最小暴露**：上下文应优先输出结构化摘要、类别、计数或脱敏值，不输出可识别的原始内容。
- **最短保留**：日志、缓存和运行时数据需定义保留目的与期限；调试数据不得无期限积累。
- **用途限制**：感知数据只能用于已声明的本地功能，不得未经明确授权上传、共享、训练、分析或用于外部服务。
- **安全日志**：日志不得包含密钥、令牌、完整剪贴板、输入文本或其他高敏感内容；异常信息同样必须经过审查。

## 3. 动作确认与执行

所有可观察到的本机变化必须遵循以下链路：

```text
感知 → 上下文 → 动作提议 → 用户确认 → 权限与策略校验 → 有限执行 → 结果审计
```

- 未获得对应动作的用户确认时，执行器不得改变文件、窗口、系统设置、设备状态或外部系统。
- 确认必须绑定具体动作、目标和风险；不得把一次确认泛化为后续动作的通行证。
- 执行器只接受经过确认门控的、结构化且已验证的请求；不得接受模型文本、插件文本或 MCP 参数的直接命令执行。
- 动作结果需记录提议、确认/拒绝、实际参数、结果和失败原因；审计记录本身也必须避免泄露敏感内容。

## 4. 插件、MCP 与跨进程边界

- 插件按不可信组件处理：必须有可验证的清单、身份、版本、入口、权限声明和数据 Schema。
- 默认最小权限；插件不能因为“需要方便”而读取无关数据、执行动作或扩展到未声明的系统能力。
- 所有插件消息、MCP 参数和跨进程输入必须校验来源、Schema、长度、类型、时间戳和权限；无效输入默认拒绝并留下安全事件。
- 不允许插件直接绕过中枢写入敏感上下文或调用执行器；动作只能经过统一确认门控。
- 新增插件框架、MCP 依赖或 IPC 通道前，要评估许可证、维护性、已知安全风险、离线降级与移除成本。

## 5. 密钥、依赖与运行环境

- 密钥、令牌、账号信息和真实个人数据不得提交到仓库、测试样例、日志或截图中。
- 依赖应锁定到可追溯版本；新增或升级依赖前需要说明用途、许可证、安全影响和替代/移除路径。
- 不运行来源不明的脚本、二进制文件或插件；外部工具必须明确来源、版本和所需权限。
- 配置默认安全：开发便利开关、调试端口和危险能力必须默认关闭，且不得在生产/演示路径中静默开启。

## 6. 变更前安全检查清单

涉及感知、日志、插件、MCP、执行器、权限或 IPC 的改动，在交付前至少确认：

- [ ] 是否新增、扩大或意外暴露了感知数据？
- [ ] 是否仍由明确用户确认控制每个本机动作？
- [ ] 是否存在绕过确认门控或直接执行文本命令的路径？
- [ ] 是否校验了不可信输入与插件权限？
- [ ] 是否在日志、测试、异常信息中泄露敏感内容？
- [ ] 是否新增了未经评估的依赖、网络访问或外部服务？
- [ ] 是否有与改动风险相称的测试，并且未削弱既有安全测试？

任何一项无法确认时，不得把改动描述为安全完成；应明确风险、停止条件和需要用户决定的事项。
