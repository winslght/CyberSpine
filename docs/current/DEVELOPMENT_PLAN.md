# 当前开发规划

本计划以“最小闭环 Demo”和“统一神经通信规范”为主线。任何新功能先接入统一消息主干，再向上扩展；不再为不同层级各自创造通信协议。

**工程定位：** 本计划描述的是 PoC 之后的正式工程建设。仓库中保留的全量感知、双节律、驾驶舱、手写 MCP 和模型编排代码曾用于概念验证；它们不是本计划的实施基线，也不得继续承载新功能。复用其已验证行为时，必须通过新主干的适配器、Schema、隐私和确认边界接入。

项目的长期目标、旧 Demo 的迁移定位、模块边界和变更准入规则以 [项目方向与主线开发章程](PROJECT_DIRECTION.md) 为准；本文件只记录实施顺序与进度。

## 阶段 0：架构基线（已完成）

- 明确最小闭环：感知 → 上下文 → 顶层大脑读取 → 用户确认 → 有限动作。
- 完成仓库顶层、命名和长期目录边界整理。
- 形成末梢插件、神经中枢、顶层大脑、确认门控的职责划分。

## 阶段 1：统一神经通信规范（当前重点）

目标是定义一份统一消息信封和一个神经信号网关，而不是并列维护多份内部协议。

**当前进度：** 已实现 `src/core/neural_message.py` 的 `NeuralMessage`、`src/core/event_queue.py` 的 SQLite 持久事件队列，以及 `src/core/neural_gateway.py` 的第一版神经信号网关。窗口感知参考末梢神经位于 `src/sensing/window_activity.py`：它已支持可见窗口目录、位置尺寸、应用/PID、前台驻留与按窗口归因的键盘/鼠标交互统计，并把状态和变化事件分开；同时在末梢内部输出有限时间窗内的焦点片段、累计专注时长/占比、切换次数与交互统计。窗口层状态现包含最大化、置顶、关联显示器、全屏几何候选及位置/尺寸变化；拖拽或调整大小仅在“鼠标按住且边界变化”时标为候选。`src/context/spinal_hub.py` 已将窗口消息经网关投影为只读上下文快照。已验证持久化、合并、投递确认、过期、网关准入、窗口消息 Schema 与上下文投影。限流、审计、路由、插件清单加载和跨进程读取仍待实现。

1. 定义 `NeuralMessage`：版本、来源、目标、时间、优先级、隐私、关联 ID、有效期、载荷 Schema 与扩展字段。
2. 固定六种消息类别：`state`、`event`、`directive`、`proposal`、`result`、`health`。
3. 定义神经信号网关的准入规则：验证、能力与权限检查、去重、限流、路由、审计和失败隔离。
4. 定义状态机：消息投递、确认、延后、过期、重试与撤销。
5. 为窗口感知准备第一份参考 Schema 和兼容性测试夹具。
6. 完成神经中枢最小只读上下文：窗口状态和事件经网关进入上下文快照，供未来 MCP 读取。

### 基础设施收敛（贯穿阶段 1 至 3）

1. 不继续扩展手写 MCP JSON-RPC 或 Ollama 裸 HTTP；待最小上下文闭环稳定后，分别迁移至成熟 MCP SDK 与官方 Ollama 客户端。
2. Windows 感知优先演进为“系统事件源 + 低频校准采样”；不再把轮询宣传为中断驱动。窗口感知首个实现使用 `SetWinEventHook` 记录前台、显示/隐藏、最小化、移动/缩放、位置与桌面切换票据，末梢按 200ms 静默窗口合并为一次冲动后只刷新受影响句柄。只有前台切换、桌面切换或完整校准有资格更新前台事实；后台窗口的几何或显示事件不得重新查询或覆盖既有前台。完整目录每 60 秒校准一次，以补偿漏事件和系统过渡。终端显示可使用不读取操作系统的本地单调时钟更新驻留与时间窗，但它不是新的感知来源，不能触发消息投递或替代系统事件。系统回调不得执行枚举、进程查询或消息投递。
3. 硬件监控、GUI 自动化和插件运行时优先采用可替换的成熟后端；统一消息、隐私、调节和确认门控继续自建。
4. 每次采用外部组件必须保留可替换适配层、离线降级与最小权限边界。

**迁移进度：** 已将项目依赖基线切换到官方 MCP Python SDK（`mcp>=1.27,<2`），并开始以只读上下文工具作为首个 SDK 适配器。旧的手写 MCP 服务保留为兼容遗留实验的过渡层，尚未删除。

## 阶段 2：仿生调节行为

1. 为每个末梢神经定义 `SensingProfile`：定期、事件和混合三种采样模式。
2. 实现持续状态快照与间歇变化事件的分离。
3. 实现局部反射：无需顶层大脑、只允许低风险和可审计的本地处理。
4. 实现下行调节：采样频率、阈值、订阅、冷却和静默范围均需有对象、期限与旁路规则。
5. 实现动作结果反馈，闭合“感知 → 提议 → 确认 → 执行 → 观察”的回路。

## 阶段 3：神经中枢与被动 MCP 适配

1. 由神经中枢汇总 `state` 和 `event`，形成只读当前上下文。
2. 持久化值得上报的升级事件。
3. 将统一消息映射为少量 MCP 工具：读取上下文、列出待处理事件、确认事件、提议动作。
4. MCP 只作为外部顶层大脑的适配接口；不承载内部核心语义。

## 阶段 4：宿主唤醒适配器

1. 在统一消息中实现可协商的 `wake_request` 语义。
2. 先实现用户确认模式：通知用户后再由宿主创建顶层大脑任务。
3. 再按不同宿主能力增加适配器；不允许神经中枢强制启动模型。

## 完成标准

每个阶段都必须有：公开 Schema、参考实现、兼容性测试、错误与隐私规则、迁移说明。任何插件或适配器若绕开统一消息网关，不进入主干。

### 主线验收标准

每一条进入新主干的闭环，除阶段自身交付外，还必须证明：

```text
事实 → 假设 → 建议 → 用户确认 → 受控动作 → 结果回写
```

其中事实必须可追溯；假设必须携带证据、置信度与不确定性；建议不得伪装为事实；动作必须绑定用户对具体目标与风险的确认。缺少任一环节的能力可以作为观察或实验存在，但不计为完成的主干闭环。
