> 状态：阶段 1 功能开发已完成，已提交并推送；当前进入注释与文档维护阶段。
> 工作分支：`feat/event-driven-window-peripheral`。  
> 基线分支：`dev`。

## 1. 本轮目标与已达成结果

本轮将窗口感知从“固定间隔全量读取”演进为：**Windows 事件驱动为主，低频校准兜底**。目标不是让任意事件都触发全量重测，而是让每类事件只更新它负责的窗口事实。

当前实现具备：

1. 使用 Windows `SetWinEventHook` 接收前台切换、窗口显示/隐藏、最小化、移动/缩放、位置变化和桌面切换事件。
2. 系统回调只写入最小事件票据；回调中不枚举窗口、不查进程、不投递消息。
3. 连续事件以 200ms 静默窗口合并为一次末梢冲动。
4. 事件冲动只更新受影响窗口；完整目录仅在启动基线和默认 60 秒校准时读取。
5. 终端每 5 秒可用本地单调时钟更新驻留时长和时间窗展示；这一脉冲不读取 Windows，不写入日志，不是新的感知来源。
6. 全局键鼠钩子只统计脱敏交互时间点；官方启动入口显式开启，Python 脚本仍可用 `--no-input-monitor` 关闭。

## 2. 当前前台状态模型

前台状态不再是简单的“有/无”。当前契约如下：

| 状态 | 含义 | 焦点归因 |
| --- | --- | --- |
| `available` | 刚刚获得可靠的前台窗口事实。 | 继续。 |
| `temporarily_unresolved` | 一次前台读取为空，保留最后确认窗口，默认最多 1 秒。 | 暂时继续，并以 `last_confirmed` 明示置信度。 |
| `unresolved` | 宽限期后仍没有可靠前台事实。不是“用户失焦”或“系统过渡态”。 | 停止新增焦点归因，等待新的前台类事件。 |
| `unavailable` | 预留给未来有明确证据的锁屏、安全桌面等状态；当前窗口插件不会仅凭空句柄输出它。 | 停止归因。 |

重要原则：**末梢看不到可靠前台，不等于用户没有前台。** 不确定性必须显式传给上层，不能伪装成事实。

## 3. 已修复的问题与根因

### 3.1 原始前台句柄偶发为空

日志证明 `GetForegroundWindow()` 在当前环境会偶发返回空，即使用户仍在 Chrome 或 ChatGPT 中工作。初版把它直接解释为 `unavailable`，造成大量伪失焦。

修复：引入一次性宽限和 `unresolved` 语义；空句柄不再直接宣称用户无前台。

### 3.2 焦点时长与未归因时长重叠

恢复前台时，旧代码无条件重写上一焦点片段的结束时间，导致已关闭片段跨越未解析区间延长，出现专注占比超过 100%。

修复：仅关闭仍处于活动状态的焦点片段；时间窗强制满足：

```text
焦点时长总和 + 未归因时长 = 观察时长
任一窗口 focus_ratio ∈ [0, 1]
```

### 3.3 后台事件覆盖已确认前台

根因是：位置/尺寸等后台事件也触发前台查询；查询瞬间为空时，增量缓存会把当前前台的 `is_foreground` 覆盖成 `false`。结果出现矛盾状态：`foreground_status=available`，但 `foreground=null`。

修复：

1. 只有 `foreground_changed`、`desktop_switched` 或完整校准可更新前台事实。
2. 后台几何、显示、隐藏等事件只更新目标窗口自身资料。
3. 非前台类事件若碰巧命中当前前台窗口，也必须保留缓存中的唯一前台标记。

## 5. 如何实测

桌面已有一键脚本：`启动窗口感知测试.bat`。双击后：

1. 静止时，驻留时长可增长，但终端应注明“本地时间脉冲（不读取 Windows）”。
2. 在 ChatGPT、Chrome、Code 间切换，应该出现对应焦点切换，新的前台驻留从 0 开始。
3. 移动或缩放后台窗口时，已确认的前台不得丢失或变为未解析。
4. 若 Windows 暂时不给前台句柄，应先显示“前台待确认”，而不是“前台不可归因”。持续无法确认时显示“前台未解析（等待系统事件）”。

命令行等价入口：

```powershell
.\.venv\Scripts\python.exe scripts\monitor_window_activity.py
```

## 7. 未解决边界与下一步建议

1. **真正的锁屏/安全桌面识别尚未实现。** 当前 `unavailable` 是预留状态；不要把 `unresolved` 简化成它。后续应先调研并采用 Windows 会话锁定/解锁与安全桌面相关的明确事件源。
2. **前台事件票据诊断性不足。** 若后续出现难以复现的错误，可在诊断模式记录脱敏的事件类别、是否携带句柄、前台事实来源；不要记录窗口标题、输入或屏幕内容。
3. **事件源性能需要长时间实测。** 重点观察高频窗口拖动、显示器切换、任务视图、托盘菜单、锁屏/解锁；不能仅凭短时测试宣称零负担。
4. **不要急于扩展浏览器标签、媒体、OCR 或输入内容。** 先稳定窗口层事实和事件语义；浏览器/媒体应作为独立末梢，不应塞进窗口感知。
5. **重新评估专注时间窗口。** 当前 `focus_window_seconds` 默认 1800 秒（30 分钟）只影响历史汇总，不影响即时前台切换；后续应区分实时驻留、短时交互统计和专注历史汇总，并评估可配置的 300/900/1800 秒档位。
