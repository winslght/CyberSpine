# CyberSpine 本地小模型推理引擎与操作系统控制能力 (运动神经元) 详细设计方案

> **历史 PoC 方案，非当前可实施规格。** 本地模型与系统控制只有在新主线完成“事实 → 建议 → 用户确认 → 有限执行 → 结果回写”后才可独立评审；本文不能授权自动化、模型常驻或扩展系统控制能力。

**文档编号**：DOC-ARCH-005  
**版本**：v4.2.0-Planning  
**核心目标**：
1. **模型端实现**：解决端侧本地轻量小模型（1.5B ~ 3B）的高性能嵌入式推理、Token 测速与冷启动问题；
2. **控制端实现**：赋予本地 AI 初步控制 Windows 操作系统的能力（运动神经元与双手执行套件），同时严守安全审批红线。

## 1. 本地 AI 模型实现方案与引擎选型

针对端侧 1.5B~3B 小模型（如 `Qwen2.5-1.5B/3B-Instruct`, `Llama-3.2-3B`, `Phi-3.5-mini`），我们设计 **三层热备混合推理引擎 (`LocalModelHub`)**：

## 2. 本地 AI 初步控制操作系统能力的实现机制 (运动神经元)

在仿生全脑区架构中，中枢 AI 控制系统的能力被抽象为 **“运动神经元与双手执行套件 (Motor Neurons & Hands Actuators)”**：

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                        CyberSpine 运动神经元执行套件 (Motor Actuators)                  │
├────────────────────────────────┬───────────────────────────────────────────────────────┤
│ 📁 目录与工作区操作器           │ ⚡ 系统稳态与电源调节器                                │
│ (WorkspaceActuator)            │ (SystemPowerActuator)                                 │
│ - 扫描工作区文件与依赖拓扑      │ - 切换 Windows 电源计划 (高性能/节能/平衡)            │
│ - 自动创建工程目录与虚拟环境    │ - 调节系统休眠超时与屏幕保护                          │
├────────────────────────────────┼───────────────────────────────────────────────────────┤
│ 🚀 应用程序与窗口调度器        │ 🔔 桌面通知与伴侣交互器                                │
│ (AppWindowActuator)            │ (NotificationActuator)                                │
│ - 调起或激活指定应用 (VSCode等) │ - 弹出 Windows 原生互动 Toast 交互卡片                │
│ - 将目标工作台窗口置顶/最小化  │ - 托盘气泡与呼吸灯动态提示                            │
├────────────────────────────────┼───────────────────────────────────────────────────────┤
│ 🌐 网络与端口诊断器            │ 🛠️ 命令行与终端执行器 (沙箱保护)                      │
│ (NetworkDiagActuator)          │ (TerminalActuator)                                    │
│ - 快速检测端口占用与网络连通性  │ - 执行只读检查命令 (如 `python --version`, `git status`)│
│ - 清理 DNS 缓存与释放端口      │ - 严格禁止高危破坏性命令 (强制删除、格式化等)         │
└────────────────────────────────┴───────────────────────────────────────────────────────┘
```

## 3. 运动神经元安全三定律 (Safety & Approval Boundary)

为了防止 AI 自作主张误操作或滥用权限，所有操作系统控制动作严格遵循 **安全三定律**：

1. **第一定律：只读操作自动放行 (Read-Only Auto-Execute)**
   * 所有无副作用的探测操作（如浅层目录扫描、状态读取、端口检查）由 AI 自主执行，写入短期记忆，毫秒级响应；
2. **第二定律：变更操作必须审批 (Mutating Actions Require User Consent)**
   * 所有对物理环境产生实质改变的操作（如启动第三方程序、创建新目录、切换电源计划、执行环境安装），**AI 必须在前端 UI 或桌面 Toast 中生成温和卡片询问用户，经用户点击同意后方可执行**；
3. **第三定律：高危破坏性操作物理熔断 (Dangerous Actions Hard-Fuse)**
   * 严禁任何形式的文件覆写删除（`rm -rf`, `format`, `del /f`）、注册表修改或未经授权的系统核心配置更改，代码层硬编码物理熔断拦截。
