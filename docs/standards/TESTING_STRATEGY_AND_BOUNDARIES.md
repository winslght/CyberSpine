## 1. 测试挑战与分层金字塔模型

CyberSpine 作为一套深入操作系统底层的具身感知系统，面临着**真实硬件环境不可控、跨平台编码差异大、端侧小模型推理非确定性**等独特挑战。

为了保证 100% 的工业级交付质量，我们构建了 **三级测试验证金字塔**：

```
                    ┌──────────────────────────────┐
                    │  【 Level 3: 端到端真机演练 】 │
                    │   (demo_minimal_loop.py)     │
                    │   - 真实硬件插拔与用户审批闭环 │
                    └──────────────▲───────────────┘
                                   │
                    ┌──────────────┴───────────────┐
                    │  【 Level 2: 跨组件集成测试 】 │
                    │   - 多信号时空对齐、呼吸节律  │
                    │   - FastMCP 资源订阅与抑制验证│
                    └──────────────▲───────────────┘
                                   │
┌──────────────────────────────────┴──────────────────────────────────┐
│          【 Level 1: 独立组件单元测试 (tests/test_component_*.py) 】 │
│           - 设备指纹计算、只读浅层嗅探、沙箱临时目录隔离与毫秒级测速  │
└─────────────────────────────────────────────────────────────────────┘
```

## 2. 关键边界条件与异常防御矩阵 (Boundary Matrix)

在每个组件研发过程中，必须针对以下边界条件进行严格的针对性测试与断言：

| 边界场景 | 极端情况描述 | CyberSpine 防御机制 | 测试断言指标 |
| :--- | :--- | :--- | :--- |
| **空盘 / 临时盘** | 插入全新未格式化或无任何文件的空白 U 盘 | 标记为 `GENERIC_STORAGE`，小脑判定为无意义物理噪音，直接静默丢弃 | 绝不上报主脑，前台 0 弹窗 |
| **权限受限目录** | 驱动器或根目录设置了 Windows 严格管理员权限 | 捕获 `PermissionError`，标记为 `RESTRICTED_PERMISSION`，不崩溃 | 异常平稳降级，耗时 $\le 5\text{ms}$ |
| **海量文件风暴** | 存储介质根目录下包含数十万个碎文件或超深子文件夹 | 严格只读遍历并在采样满 50 个文件或达到 MaxDepth=2 时强制 `break` 退出 | 嗅探耗时强行断言 $< 50\text{ms}$ (实测 $2.1\text{ms}$) |
| **重复插拔熟客** | 同一物理设备在短时间内反复插拔或切换 USB 接口 | 基于硬件特征与卷标计算 SHA-256 唯一指纹，自动继承历史打标 | `dev1.device_id == dev2.device_id` 且 `is_known=True` |
| **终端非 UTF-8** | 中文 Windows CMD/PowerShell 默认 `GBK (CP936)` | 自动探测并调用 `sys.stdout.reconfigure(encoding='utf-8')`，控制台统一使用标准 ASCII 标签 | 0 `UnicodeEncodeError` 崩溃 |
| **时区跨越** | 宿主机在不同时区或跨夏令时运行 | 统一使用带有时区信息的 `datetime.now(timezone.utc)` | 时间戳严格符合 ISO 8601 标准 |

## 3. 双轨测试验证手段 (Dual-Track Testing)

### 3.1 轨道一：自动化 Mock 虚拟信号注入 (Automated Mock Track)
* **适用场景**：CI/CD 自动化流水线、开发者本地无物理外设时的快速回归；
* **实现方式**：
  * 在 `tempfile.mkdtemp()` 中动态构建包含特征工程文件的虚拟沙箱目录；
  * 调用 `mock_inject_storage_signal()` 生成合规的 `RawSomaticSignal`；
  * 测试完毕后在 `tearDown()` 中自动彻底清理临时文件，不留任何磁盘垃圾。

### 3.2 轨道二：硬件真机插拔与现场演练 (Live Hardware Track)
* **适用场景**：发版前验收、真实外设体验评估；
* **执行入口**：`python demo_minimal_loop.py`；
* **操作流程**：
  1. 启动脚本，系统自动刷新当前挂载磁盘基线；
  2. 用户在物理机插入真实 U 盘（如三星 T7、闪迪优盘）；
  3. 控制台实时打印末梢感知 ➔ 时钟缓冲 ➔ 小脑意图 ➔ 大脑接管执行的全过程。
