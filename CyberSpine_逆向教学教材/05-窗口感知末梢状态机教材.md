# 05：窗口感知末梢状态机教材

这一章将 `src/sensing/window_activity.py` 当作一台小型、长期运行的状态机来理解。它是当前新主线代码里最复杂、最接近真实 Windows 的部分。不要从结尾的“生成消息”往前猜；应从输入事实、内部记忆、消息输出三个层次读。

## 1. 它的任务边界是什么

`WindowActivityPeripheral` 的任务是**产生可由本地 Windows 元数据和单调时钟证明的窗口事实**。它不是：

- 不读取窗口标题、屏幕像素、键值、输入文本、剪贴板或鼠标坐标；
- 不猜“用户正在写代码”“用户意图是打开项目”；
- 不自己写入 gateway 或 SQLite；
- 不自己决定是否调用模型或执行器。

它的唯一输出形态是 `list[NeuralMessage]`。调用者可以是 window monitor，也可以是 `NeuralSpinalHub`。二者决定消息下一站，末梢不决定。

## 2. 输入：三个独立来源

```text
WindowsWindowEventSource         WindowsWindowInventory       WindowsGlobalInputMonitor
  SetWinEventHook                  EnumWindows / HWND          keyboard/mouse LL hooks
  -> WindowEventTicket             -> raw window records         -> hwnd + time / button-held
  （变化提示）                       （实际事实）                    （聚合交互证据）
             \                         |                         /
              \                        |                        /
                       WindowActivityPeripheral
```

### 2.1 `WindowsWindowEventSource`：变化提示，不是事实

文件：`window_events.py`。

它监听的 event code 映射包括前台切换、移动/缩放开始/结束、最小化开始/结束、桌面切换、显示/隐藏和位置改变。事件线程用 `WINEVENT_OUTOFCONTEXT | WINEVENT_SKIPOWNPROCESS`，每个 callback 还通过 `accepts_callback()` 过滤 `EVENT_OBJECT_*` 的非顶层子对象。

callback 只创建：

```python
WindowEventTicket(kind: str, hwnd: int, occurred_at: float)
```

它包含 HWND，但不包含 title、窗口记录或 payload。这个设计的关键是**把“Windows 告诉我可能变了”与“我读取确认事实”分开**。没有这层分离，callback 内 `psutil`、窗口枚举、复杂状态计算会阻塞系统事件线程。

### 2.2 `WindowImpulseCoalescer`：为什么不是每个 WinEvent 都发消息

窗口拖拽、缩放和 UI 变化会在短时间产生很多事件。`WindowImpulseCoalescer` 用默认 0.2 秒的静默窗：每接收一个 ticket，就按调用线程当前单调钟刷新 `_last_ticket_at`；只有之后 200ms 没有新 ticket，`drain_ready()` 才返回整批并清空。

这里不信任 ticket 自身的时间戳来跨线程计时，是为了避免 callback 和调用线程时钟/调度不同造成过早合并。这减少 OS 读取和重复消息，不会丢失“该批期间发生过哪些类别”的诊断事实。

### 2.3 `WindowsWindowInventory`：实际读取的数据

文件：`window_inventory.py`。

`list_windows()`：

1. `GetForegroundWindow()` 得到当前 HWND；
2. `EnumWindows()` 枚举顶层窗口；
3. `_is_user_window()` 先要求 visible，再排除 tool window；
4. 每个保留窗口调用 `_window_record()`；
5. 如果前台窗口因 tool style 未进入列表，仍额外插入，因为前台是核心事实；
6. 对目录内项重新赋 Z 顺序。

`_window_record()` 通过 `GetWindowThreadProcessId`、`GetWindowRect`、`IsIconic`、`IsZoomed`、扩展 style、`MonitorFromWindow`/`GetMonitorInfoW` 取得：HWND、PID、进程名、边界、最小化/最大化/置顶、关联显示器。进程名从 `psutil.Process(pid).name()` 取得，有 TTL/上限 cache；访问被拒绝时变为 `system_protected`。窗口标题没有被取用。

`foreground_window()` 例外地允许前台 tool window 成为焦点事实。这样“用户正在一个 tool window 上”不会被目录过滤后错误表示为“没有前台”。

### 2.4 可选 input monitor：只做频率，不记录输入内容

`WindowsGlobalInputMonitor` 在显式 `start(input_monitor=True)` 时启动。回调遇到 key-down 或鼠标动作，只调用 `GetForegroundWindow()`，再把 HWND 交给 `_record_hwnd_interaction()`；鼠标按下/抬起仅更新一个“是否有任何按钮仍按住”的布尔集合。

`WindowInteractionTracker` 将每个 `window_id` 的单调时间点放在 deque 中。`summary()` 清除滑动窗口外的时间点，返回：

```text
period_seconds, event_count, events_per_minute,
is_high_frequency, last_interaction_monotonic
```

滚轮是一次 interaction，但不是按钮按住。X1/X2 从 `mouseData` 解码为独立按住状态。这个实现的表达力有限：`mouse_button_held + geometry change` 只是拖动的候选证据，不能证明用户真的拖动了窗口。

## 3. 内部状态：为什么对象有这么多字段

初始化中的字段可以按职责分组：

| 组 | 字段示例 | 解决的问题 |
|---|---|---|
| 数据源 | `_inventory`、`_catalog_provider`、`_screen_bounds_provider`、`_event_source` | 真实 Windows 与测试注入可使用同一状态机。 |
| 时间窗口 | `_activity_window_seconds`、`_focus_window_seconds`、`_focus_segments`、`_unattributed_intervals` | 输出驻留、聚焦比例和未归因时间。 |
| 前台真相 | `_last_observed_foreground`、`_last_confirmed_foreground`、`_foreground_unresolved_since`、`_foreground_resolution` | 抵抗 `GetForegroundWindow()==0` 的短暂过渡。 |
| 目录增量 | `_catalog_cache`、`_last_observed_catalog` | 不必每个 event 都 `EnumWindows`，但仍保留校准。 |
| 几何 | `_last_geometry`、`_pending_geometry_changes`、`_mouse_button_held` | 比较连续边界，形成 geometry event。 |
| 去噪 | `_last_published_fact_signature`、`_event_coalescer` | event storm 或内部系统表面不伪装成新用户事实。 |
| 观测健康 | `_event_diagnostics_enabled`、error count properties | 输出计数而非底层异常/敏感数据。 |

这不是“字段多就是不好”；Windows 的异步性质确实需要部分历史。但同一对象承担这么多时序状态，是维护时要先写/读测试的原因。

## 4. 前台解析：三态和一次性宽限

`_resolve_foreground(raw_foreground, now)` 是最重要的防误判逻辑：

```text
有 raw foreground
  -> 保存 last_confirmed
  -> available / raw_foreground_present

没有 raw foreground，且从未有 baseline
  -> unresolved / no_foreground_baseline

没有 raw foreground，但有 last_confirmed，且宽限 < foreground_grace_seconds（默认 1s）
  -> temporarily_unresolved
  -> 返回 last_confirmed 的副本

没有 raw foreground，宽限已到
  -> unresolved / foreground_resolution_timeout
```

为什么不让 `collect_local_time_messages()` 的 UI 刷新自动把 temporarily unresolved 变成 unresolved？因为展示节奏不是操作系统事实。`_local_foreground()` 明确只返回最后观察到的前台和现有状态；真正推进到最终 unresolved 的，是 `collect_foreground_resolution_messages()` 的一次性重读。

这样避免了常见假象：输入法/安全桌面/shell 切换的短空窗口，被错误报告为用户注意力突然中断。

## 5. 全量校准与增量事件路径

### 5.1 全量路径

`_observed_catalog()` 在无 event tickets、无 inventory cache、desktop switch 或测试 provider 情况下：

```text
catalog_provider() -> raw list
-> _normalize_window(raw, index)
-> _catalog_cache = {window_id: item}
-> 找 is_foreground
->（兼容 snapshot_provider 时可用 _legacy_snapshot）
```

这是权威“校准”路径，能重建窗口增删和全局 Z 顺序。

### 5.2 增量路径

有 ticket、存在 real inventory 和 cache，且 ticket 都有 HWND 且不是 desktop switch 时，`_event_catalog()`：

1. 对受影响 HWND 调 `window_for_handle()`；
2. 背景窗口消失就从 cache 移除；已确认前台暂时读不到时保留；
3. 只有前台改变、桌面切换、或当前前台 hide/minimize 时才重读 `foreground_window()`；
4. 空前台重读时，只有明确 `foreground_changed` ticket 才把 ticket HWND 当补充证据；
5. 不受影响项保持原 Z 顺序，只同步前台标记。

这条路径节省全量枚举，但它也意味着 cache 可能暂时落后于真实系统。低频完整校准就是校正器，不能删。

## 6. 装饰阶段：把原始记录变成公开事实

`_decorate_catalog(catalog, foreground, now)` 依次：

1. 有 foreground 时 `_observe_focus()`，否则 `_observe_unattributed()`；
2. 将 raw window 交给 `_public_window()`，去掉 `hwnd` 等内部字段；
3. `_presentation()` 识别 ordinary/user-presented/system-surface；
4. `_window_state()` 判断最大化、置顶和“覆盖关联显示器”的 fullscreen candidate（不是像素/独占全屏检测）；
5. `_observe_geometry()` 形成几何事实；
6. 添加前台驻留秒数和 `WindowInteractionTracker.summary()`。

输入法等系统表面会更新内部几何 baseline，但不发 geometry event；这很微妙：若完全忽略它们，下一次真实窗口对比可能用到陈旧基线；若发布它们，又会制造大量无关神经信号。

`_is_synchronized_shell_surface()` 还用严格条件把与系统表面边界同步的、无标题、非前台的 `explorer.exe` 伴生表面降噪，普通有标题资源管理器不匹配。

## 7. 几何和全屏：报告的是“候选”，不是意图

`_observe_geometry()` 的首次观察只写 baseline；之后比较 left/top/width/height 和 display id：

- 不变：`stationary`；
- 改变：`moved`、`resized`、`moved_and_resized` 或 `display_changed`；
- 按钮仍按住并且移动/缩放：加 `_candidate`，`detection_basis` 指向鼠标按住与几何改变；
- 其他改变：`geometry_changed`，basis 为无拖动证据的几何变化。

`_window_state()` 仅当窗口没有最小化并且边界和关联 display 相差不超过 2px 时给 `is_fullscreen_candidate=True`。这不是读取像素、DXGI 独占状态或 app 语义，故措辞必须是 candidate。

## 8. 时间账本：focus segment 与 time window

窗口末梢不仅报告“现在是什么”，还维护有限时窗内“刚才持续了多久”。`_observe_focus()` 会：

- 首次前台建立 `_history_started_at` / `_foreground_started_at`；
- 同一窗口只延续；
- 前台切换时关闭前一 segment、开新 segment；
- `_prune_focus_history()` 将过期片段裁剪/删除。

无前台时 `_observe_unattributed()` 打开未归因 interval；恢复时 `_close_unattributed()` 关闭它。`_time_window_message()` 汇总 observed、unattributed、coverage、focus switch、segments 和 windows；因此“未归因”是诚实的数据质量表示，而不是强行把全部时间归给上一个应用。

## 9. 最终的七种消息

| topic / schema | kind | 何时出现 | payload 核心 |
|---|---|---|---|
| `window.current_state@3` | STATE | 每批事实 | foreground、count、resolution、各 error count。 |
| `window.catalog@1` | STATE | 每批事实 | windows 和 count。 |
| `window.time_window_summary@1` | STATE | 每批事实/本地时间刷新 | 时间段、segments、应用汇总、coverage。 |
| `window.focus_changed@2` | EVENT | 前台窗口变化 | previous/current。 |
| `window.high_interaction_changed@1` | EVENT | 高频交互窗口集合改变 | previous/current ids 与 period。 |
| `window.foreground_availability_changed@1` | EVENT | available/unresolved 类状态变化 | previous/current/reason/recovered foreground。 |
| `window.geometry_changed@1` | EVENT | `_pending_geometry_changes` 非空 | changes。 |

三类 state 使用 `collapse_key` 的价值在 gateway queue 中才体现：如果后续 consumer 处理不过来，最新 current/catalog/time 可以替代旧 state；event 不能这么做。

## 10. 事实签名与事件去重

`_fact_signature()` 排除 `focus_dwell_seconds`、`interaction` 和 `geometry_activity` 这种本地派生、会随展示脉冲变化的字段，并从签名中排除 `presentation.state == system_surface`。如果 event ticket 批次的签名和上次已发布完全相同，`collect_messages()` 直接返回空列表。

它保护的是“不要把重复 WinEvent 说成新事实”。它不意味着没有发生系统事件，也不代表事件丢失；诊断模式仍能观察合并后的 ticket kind/count。

## 11. 维护本模块时的安全阅读顺序

先选一个真实问题类别，再读匹配测试：

| 问题 | 首看函数 | 再看测试/相邻函数 |
|---|---|---|
| 前台瞬间消失 | `_resolve_foreground`、`collect_foreground_resolution_messages` | `foreground_resolution_due_seconds`、测试中的 grace 场景。 |
| 拖拽/窗口移动事件多 | `WindowImpulseCoalescer`、`_observe_geometry` | `_fact_signature`、input hook 的 mouse held 处理。 |
| 某应用/IME 制造噪音 | `_presentation`、`_is_synchronized_shell_surface` | signature 过滤和 system surface geometry suppression。 |
| 统计时间不对 | `_observe_focus`、`_observe_unattributed`、`_time_window_message` | prune/cutoff 逻辑。 |
| 网关拒绝窗口 payload | 先看 `payload_schema` 和生成函数 | `src/core/schema_validation.py` 的精确白名单。 |

不建议把旧 app 的“意图/简报”判断搬进这里。这样会把硬件事实、隐私过滤、状态机和业务推断混在一个最难测试的类里。
