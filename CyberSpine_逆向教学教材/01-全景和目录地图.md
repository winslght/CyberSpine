# 01：全景和目录地图

## 1. 先把仓库切成四块，而非一团“AI 代码”

```text
CyberSpine/
├─ 新主线：src/core + src/context + src/sensing + adapters/mcp
│  └─ 目标是：不可信末梢消息先被准入、持久化和脱敏，再供上层只读
├─ 历史 PoC：src/perceptors + pacing + cortex + app + mcp + actuators
│  └─ 目标是：把许多系统读数汇总成演示用简报、MCP 工具和驾驶舱
├─ 运行/演示脚本：scripts/、*.bat
│  └─ 同名“monitor”不是生产 daemon；脚本各自拥有独立启动方式
└─ 证据与资料：tests/、plugins/、docs/、runtime/、vendor/
   └─ 测试可证明局部契约；docs 只能解释意图，不能证明功能接通
```

两条路线共享部分 Windows 窗口感知代码：历史 `ForegroundFocusPerceptor` 会使用 `WindowActivityPeripheral`，但它把结果重新包装成旧 `RawSomaticSignal`；它没有调用 `NeuralSignalGateway`。这不是“新旧兼容层已建成”，而是代码层面的共享依赖。

## 2. 根目录：哪些是运行开关，哪些不是

| 路径 | 职责与现状 |
|---|---|
| `pyproject.toml` | Python 包与依赖声明（Pydantic、MCP、psutil；开发依赖 pytest/ruff/mypy）。没有 `console_scripts`，因此**没有** `pip install` 后的正式命令行入口。 |
| `start_window_monitor.bat` | 启动 `scripts/monitor_window_activity.py --input-monitor` 的 Windows 便捷入口。它会实际启动 WinEvent 与可选低级输入钩子。 |
| `scripts/start_cockpit.bat` | 启动旧 `src/app/cockpit_app.py`。这不是新主线 daemon。 |
| `scripts/run_demo.bat` | 启动 `scripts/demo_minimal_loop.py`；后者有显式 mock storage simulation。 |
| `.mcp_config.example.json`、`.env.example` | 配置样例，不是已装配的运行配置。 |
| `AGENTS.md` | 当前仓库的开发授权、安全边界；不是程序代码，但对修改行为有效。 |
| `runtime/data/device_inventory.example.json` | 示例运行数据；不是自动维护的真实设备数据库。 |
| `vendor/aida64/` | AIDA64 配置/说明，供旧硬件感知器寻找外部程序；仓库并未实现或捆绑完整 AIDA64 运行时。 |

根目录中还可能有 `.test-tmp/`、`.pytest-tmp-*`、`.tmp/`、`.pytest_cache/`、`.ruff_cache/` 与 `cyberspine.egg-info/`。它们是测试、工具或安装生成物，不属于产品源代码树，也不应被解读为功能模块。

## 4. 新主线逐文件地图

### `src/core/`：中枢的纯领域层

| 文件 | 为什么存在 | 关键对象 | 实现判断 |
|---|---|---|---|
| `neural_message.py` | 让所有新消息使用同一个信封，而不是散乱 dict。 | `NeuralMessage`、`MessageKind`、`MessagePriority`、`PrivacyClass` | **[实]** Pydantic 模型、TTL 计算。 |
| `event_queue.py` | 将通过准入的消息保存到 SQLite，并给将来的消费者一个状态机。 | `DurableEventQueue`、`QueueItem`、`DeliveryStatus` | **[实]** 只有队列；没有消费者服务。 |
| `neural_gateway.py` | 唯一入队前门；兼容旧窗口末梢和新的 manifest/session 路径。 | `NeuralSignalGateway`、`PeripheralRegistration` | **[实/装配]** 两种 publish 路径均存在。 |
| `plugin_manifest.py` | 在执行任何插件前，仅验证声明的结构及运行时字符串是否安全。 | `PluginManifest`、`PluginRuntimeSpec`、`load_manifest()` | **[实]** 不加载、不启动 runtime。 |
| `plugin_registration.py` | 把已验证 manifest 与本地 grant 绑定并发短期 session。 | `PluginGrant`、`PluginSession`、`RegistrationRegistry` | **[实]** 纯内存，重启即丢。 |
| `gateway_admission.py` | 将协议、来源、topic、kind、隐私、时间、大小和 payload 校验做成可测试的纯准入政策。 | `AdmissionPolicy.admit()` | **[实]** 目前只认识七个窗口 schema。 |
| `schema_validation.py` | 防止 payload 夹带标题、路径、文本、剪贴板等敏感字段，并严格白名单字段。 | `validate_payload()`、`WINDOW_PAYLOAD_VALIDATORS` | **[实]** 对未知 schema fail closed。 |
| `message_limits.py` | 防超大、深嵌套、非 JSON payload 写入 SQLite。 | `MessageLimits` | **[实]** 默认 64 KiB、深度 8、集合 128。 |
| `flow_control.py` | 避免一个会话/主题发送风暴。 | `RateLimitPolicy` | **[实]** 内存 token bucket；重启/过期 session 后不清桶。 |
| `plugin_health.py` | 基于网关观察的拒绝次数和最后出现时间判断实例健康。 | `PluginHealthMonitor` | **[实]** 是判断器，不会杀进程。 |
| `isolation_policy.py` | 把健康结论转换为“应不应抑制上游”的纯决定。 | `IsolationPolicy` | **[预留]** 没有执行隔离/停止 runtime 的调用者。 |
| `audit.py` | 给网关提供不含 payload 的审计最小契约。 | `AuditEvent`、`AuditSink`、`MemoryAuditSink` | **[实/测]** 默认仅内存，进程退出即消失。 |
| `gateway_errors.py` | 用稳定枚举而非原始数据形成拒绝结果。 | `GatewayRejected`、`GatewayRejectionCode` | **[实]** 但异常对象仍有 `detail`，调用者不可随意回显。 |
| `__init__.py` | 对外再导出核心类型。 | — | 包边界。 |

### `src/context/`：允许向上读、禁止向下执行

| 文件 | 职责 |
|---|---|
| `current_context.py` | `CurrentContextStore.ingest()` 将 public/metadata 的 state 覆盖为当前值、health 覆盖为当前值、event 保留最近 32 个；`snapshot()` deep-copy。 |
| `read_service.py` | `CurrentContextReader` 把 snapshot 包成版本化 `cyberspine.current_context@1` JSON；不采样、不入队、不执行。 |
| `spinal_hub.py` | 小型装配器：Queue + Gateway + ContextStore + WindowPeripheral；`collect_window()` 的顺序是 publish 成功后才 ingest。 |
| `__init__.py` | 再导出这些类型。 |

### `src/sensing/`：当前最成熟的新末梢

| 文件 | 职责 |
|---|---|
| `window_activity.py` | 事实整合状态机。输出 current/catalog/focus/activity/time/availability/geometry 七类消息；不做意图推断。 |
| `window_inventory.py` | Windows `EnumWindows`、前台窗口、窗口矩形、显示器和进程名缓存；输出窗口元数据，未读取标题。 |
| `window_events.py` | `SetWinEventHook` 线程只排入 `WindowEventTicket`；调用线程随后读取事实，`WindowImpulseCoalescer` 以 200ms 静默窗口合并风暴。 |
| `window_interactions.py` | 可选键盘/鼠标低级 hook，只保存时间点和前台 HWND；上层只见聚合频率。 |
| `window_activity_log.py` | JSONL 追加/轮转以及离线摘要分析；它写原始 `NeuralMessage`，是否适合长期保留须另行治理。 |
| `__init__.py` | 只导出 `WindowActivityPeripheral`。 |

### `src/adapters/mcp/`：只有读端工厂

`context_server.py:create_context_server(reader)` 使用官方 `FastMCP` 注册一个 `cyberspine_get_current_context()` 工具。它无法自行生成 reader、启动感知或管理 stdio 生命周期；所以它是**[预留/测]**，而不是“新 MCP 已上线”。

## 5. 历史 PoC 文件地图（存在 ≠ 新主线）

| 目录/文件 | 实际职责与局限 |
|---|---|
| `perceptors/base.py` | 旧 `BasePerceptor` 抽象。 |
| `perceptors/somatic_hub.py` | 构造十余个旧 perceptor，顺序 `poll_all_signals()`；再可喂入 `TemporalNeuralBuffer`。它是高耦合服务定位器。 |
| `perceptors/system/*.py` | 焦点、运行程序、负载、电池、通知、稳定性、输入、剪贴板等。部分读取 `psutil` 或 Win32，`QueuedNotificationsPerceptor` 与 `SystemStabilityPerceptor` 明确有 mock trigger；不可一概叫“真实系统监听”。 |
| `perceptors/io/*.py` | 设备库、浅层目录探测、管理器；`IOPerceptorManager.mock_inject_storage_signal()` 是 demo/e2e 的主要输入。 |
| `perceptors/hardware/*.py` | AIDA64 shared memory 尝试与 native fallback；依赖外部运行环境。 |
| `perceptors/network/network_health.py` | 对默认 `1.1.1.1:53` 建连测连通性，属于真实网络 I/O，不能在离线/受限环境中当作稳定功能。 |
| `pacing/neural_buffer.py` | 旧信号短窗聚合与 inhibition。 |
| `pacing/real_pacemaker.py` | 单例后台循环，定时 poll old hub 并生产面向驾驶舱的 tick/briefing。 |
| `models/somatic_signals.py` | 旧 `RawSomaticSignal`、`FusedSomaticPacket` 等模型；与新 `NeuralMessage` 是两套契约。 |
| `models/local_engine.py` | 可选调用本机 Ollama；失败时用规则性简报/提议。它不是新网关 consumer。 |
| `spinal_core/intent_gate.py` | 旧的意图叙事规则。 |
| `cortex/master_cortex.py` | 旧认知与文件扫描示例；默认 approval 行为值得安全复审。 |
| `actuators/` | `SafetyGate`、workspace/app/power 三类执行器。依赖运行时回调传入 approval；没有与新 gateway 审计绑定。 |
| `app/app_bridge.py` | 旧驾驶舱后端、内存插件状态和展示数据的混合体；里面有大量硬编码名称/状态/文案。 |
| `app/cockpit_app.py` + `ui/` | pywebview 驾驶舱启动与静态网页资源。 |
| `mcp/server.py` | 手写 JSON-RPC stdio server，创建旧 `CyberSpineMCPHandlers`。 |
| `mcp/tools.py` / `schemas.py` | 旧 MCP 工具及 schema；tool call 可路由到旧执行器。 |

## 6. plugins、scripts、tests 为什么存在

| 路径 | 正确理解 |
|---|---|
| `plugins/builtin/window_activity/manifest.json` | 新 manifest 输入样本，也是 gateway monitor 可读的真实内置声明；它没有触发自动加载。 |
| `plugins/examples/mock_storage_nerve/` | BNP 老协议的 stdio **示例**，使用 `nerve/pulse`，不是新 `NeuralMessage` 插件。 |
| `scripts/monitor_window_activity.py` | 最接近真实窗口末梢运行的观察器；协调事件、宽限重读、展示脉冲和校准，写日志。 |
| `scripts/monitor_gateway.py` | 新 gateway 的安全终端观察器；临时队列、临时 session，输出计数。 |
| `scripts/monitor_gateway_admission.py` | 更早/更简单的 stdin 或短期 demo 观察器；同样不是 daemon。 |
| `scripts/analyze_window_activity_log.py` | 对既有 JSONL 做摘要。 |
| `scripts/demo_minimal_loop.py` | 历史 demo，默认能进入 mock storage 方案；不应拿来证明硬件自动发现。 |
| `tests/core/` | 覆盖新 gateway 的 message、queue、manifest、registration、admission、governance。 |
| `tests/context/` | 证明 `NeuralSpinalHub` 这种装配可用，恰好也证明它尚未作为启动器存在。 |
| `tests/sensing/` | 大量注入 catalog、clock、ticket 的状态机测试，不能替代真实 Windows 桌面验收。 |
| `tests/integration/test_window_gateway_contract.py` | 用 fake catalog 验证末梢—legacy gateway 的契约。 |
| `tests/scripts/` | monkeypatch peripheral 的 CLI 行为测试。 |
| `tests/e2e/` 与根 `tests/test_*.py` | 主要覆盖历史 PoC；其“e2e”不等于新系统端到端。 |
