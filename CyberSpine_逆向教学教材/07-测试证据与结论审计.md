# 07：测试证据与结论审计

本章让你区分三种完全不同的话：

1. “代码写了某个分支”；
2. “测试曾针对该分支断言过”；
3. “本次在这台机器、这个工作区、这个 Windows 环境运行成功”。

本教材以 1 和 2 作为代码考古证据；**没有在本次写文档时运行测试**，因此绝不把 2 写成 3。

## 1. 本次取证方式

已阅读当前工作区的：源文件、脚本、manifest、测试代码、Git 状态与调用引用。没有把 README/设计文档用作实现证据；没有启动 window hook、驾驶舱、Ollama、MCP 或执行器；没有运行 pytest，以避免向项目写入临时文件或碰到真实系统 I/O。

当前 Git 状态在开始时已存在下列非本教材改动：`src/core/*` 的 gateway 相关文件、`src/context/spinal_hub.py`、gateway tests/scripts、`docs/INDEX.md` 等。教材将其当作当前工作区事实，不归属、不修改。教材自身只新增 `CyberSpine_逆向教学教材/`。

## 3. 窗口末梢测试为什么仍然很有价值

`tests/sensing/test_window_activity.py` 大量使用可注入的 `catalog_provider`、clock、ticket 和 interaction tracker。它不是“假测试”，反而是让复杂时序可重复的必要条件。它适合证明：

- 空前台宽限不会被 UI 时间脉冲推进；
- event batch 与 full catalog 何时走不同代码；
- focus/time accounting 规则；
- geometry baseline、拖拽候选、显示器切换；
- system surface 降噪与 signature dedup；
- 公开 payload 不携带不该有的字段。

它不能证明：钩子在当前 Windows 版本安装成功、权限允许、任意真实 IME/应用的窗口树都符合假设、长时间运行无 resource leak。故“测试覆盖状态机”与“真实桌面验收”必须并列进行。

## 4. 旧 PoC 测试名称的陷阱

根目录 `tests/test_end_to_end_mvp.py`、`tests/e2e/` 的命名会让人误以为系统级生产验收。读代码会发现其中许多路径创建 mock USB 目录、调用 `mock_inject_storage_signal()`、mock notification/crash event、替换方法或检查内存对象。它们有价值：证明历史演示链在指定 fake 输入下不会立即断裂；它们不能证明真实设备热插拔、真实通知中心、真实 crash log、真实 MCP 用户确认或新 gateway 已串通。

当你看到测试名包含 `real_world`、`integration`、`e2e` 时，请继续问三个问题：

```text
输入从哪里来？（真实 OS / fake / monkeypatch / 临时文件？）
断言的输出是什么？（内存对象 / 日志 / 外部可观察副作用？）
它有没有经过今天用户真正会启动的入口？
```

## 5. 可执行验证路线（仅供获得另一次运行授权后使用）

以下不是本次执行记录，而是以后重新接管时可选择的验证顺序。所有命令都会产生运行时副作用（临时 DB、日志、Windows hook 或测试缓存），应在当时确认范围后运行。

```powershell
# 1. 纯新核心（通常只写测试临时目录）
.venv\Scripts\python.exe -m pytest tests\core tests\context tests\integration -q

# 2. 观察脚本的 CLI/Fake 覆盖
.venv\Scripts\python.exe -m pytest tests\scripts -q

# 3. Windows 末梢状态机单测
.venv\Scripts\python.exe -m pytest tests\sensing -q

# 4. 手工、短时、脱敏窗口观察（会启动 hook 并写 runtime 日志）
.venv\Scripts\python.exe scripts\monitor_window_activity.py --duration 10

# 5. gateway 的真实窗口短期入队演示（临时 DB）
.venv\Scripts\python.exe scripts\monitor_gateway.py plugins\builtin\window_activity\manifest.json --window-snapshot --duration 10 --no-clear
```

若 pytest 出现 Windows 临时目录 `PermissionError: [WinError 5]`，需要把“测试环境无法建/删临时目录”与“断言失败”分开报告；前者不能拿来推断 gateway 逻辑错误，后者也不能被环境问题掩盖。

| 结论 | 主证据文件 |

1. 任何涉及当前实际桌面、Ollama、Windows hook、外部网络、设备、执行器的结论都是代码路径存在的结论，不是本次实机运行成功的结论。
